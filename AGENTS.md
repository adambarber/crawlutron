# AGENTS.md

This file provides guidance to agents working in this repository.

- The service is a stateless execution surface. Callers own frontier queueing, dedupe, persistence, and host-policy decisions; do not add caller state to the service to make a caller's problem easier.
- Agent/bot integrations should use the machine-readable discovery endpoints first (`/.well-known/crawler-service` and `/v1/capabilities`) and follow the durable contract in `docs/references/crawlutron-agent-contract.md`.
- It must not bypass Cloudflare or WAF controls, solve CAPTCHAs, rotate proxies or identities, inject credentials, or continue after an explicit denial. Terminal classifications are reported, not worked around.

## Agent dispatch rules (process)

- **Pre-development review before any feature or fix.** Read the ticket, the modules it touches, and the gates that govern them; state how the change fits the current architecture before writing code. A ticket whose body cites stale paths must be re-grounded from the live tree first.
- **Architectural review gate on tickets.** A GitHub ticket must carry an architectural review (its reach, its design choice, its walk-past plan) before an implementation agent picks it up. A quick `scripts/ticket_arch_review.sh <issue>` check assists the reviewer; it does not replace the review.
- **All development is TDD.** Red first for every behavior; record the red output; then green; then refactor. Budgets and ratchets move DOWN only, in the same commit as the work that earns them.
- **Gates seal shut at zero.** When a gate's offender count reaches zero, delete its budget/exemption table and leave an unconditional assertion — no configuration surface survives a sealed gate. Verify with a mutation check (inject the violation; the gate must name file and line).
- **Document process improvements here.** Any change to dispatch rules, review requirements, or gate doctrine is written into this section in the same commit that lands it.
- **Commit verification trap (2026-10-25, three occurrences):** never pipe a commit through `tail`/`grep` (the pipe swallows pre-commit's exit code — exit 0 with nothing landed); never compound `--no-verify` into a multi-statement command; after every commit attempt verify `git log -1` shows the expected message BEFORE proceeding.
- **Hook budget stays inside turn budgets (rewritten 2026-10-27, gate-speed audit):** every gate runs THROUGH `scripts/gate_fanout`, which starts all gate children at once on the first hook of a run and lets each hook wait only on its own child — wall time is the SLOWEST gate, not the sum. Each fan-out child is hard-killed after `WALL_SECONDS = 60` (`scripts/gate_fanout.py`), so no gate can hang a commit; a hang is a gate defect, never a reason to skip it. Measured on the reference machine (warm): full chain 15.9s — ruff 0.23s, ruff-format 0.17s, pyright 4.28s, jscpd 0.17s, mypy 0.17s, vulture 0.18s, safety-invariants 10.0s (`-n 6` xdist; serial 35.6s; slowest legit invariant 3.3s). Every gate still runs on every commit — exclusion, `--no-verify`, and budget raises are forbidden; the jscpd floor tightened 3/30 → 2/30 in the same audit (zero pairs measured over 687 sources). When a gate or invariant test is added, the chain must stay fast enough for a subagent to complete a commit inside one turn; if the warm chain grows past ~25s, parallelize further rather than trimming tests. A cold chain (fresh workspace, no `.mypy_cache`/`.gate_fanout`) is the number a subagent hits on workspace up — keep it under ~60s or pre-warm caches in the workspace setup steps.
- **Subagent dispatch protocol (user directive 2026-10-27, mandatory for every dispatch):** the FIRST thing a dispatched subagent does, before any other work, is validate its environment: (1) confirm `git rev-parse --show-toplevel` and `git branch --show-current` name its assigned hardstand workspace and `work/*` branch — never main, never another writer's workspace; (2) confirm its tools work (`.venv/bin/python` resolves, `pytest` collects, pre-commit hooks are installed); (3) confirm it has the ticket context, directions, and workspace path it needs. If ANY check fails, it MUST send the parent a message describing the failure and HALT until it receives direction — zero improvisation, zero workspace-hopping. Additionally, every subagent ENDS every turn with a SELF IMPROVEMENT REVIEW: what its instructions failed to cover, what process friction it hit, and what the parent should change to make the next dispatch succeed. The child writes it into its final report text (child sessions have no ctx_memory tool); the parent reads every review and folds accepted improvements into this section — the improvement cycle is part of the dispatch itself, not an afterthought. Dispatch-prompt checklist for the parent, from accumulated reviews: name how to read CLOSED issues (`state:"all"`), tell writers to run `ruff check` before committing (blocked commits are the gate working — never auto-fix to mask them), and state the expected layer/package for ownership moves rather than leaving it to the writer's judgment. Pre-flight additions (2026-10-27, BU review): every writer merges main FIRST (`git merge main --no-edit`) — ticket-referenced files may have moved since the branch diverged; grep tests/ and docs/ for a source path string before any `git mv` (four path-pinning invariants need same-commit edits); tools with path parameters get ABSOLUTE in-workspace paths (ast_grep_replace resolves against the parent checkout otherwise).
- **Hardstand adoption mandate (user directive 2026-10-24):** all implementation agents run inside their hardstand workspace only (config: hardstand.toml, workspaces under `.hardstand/` INSIDE `~/Projects/crawlutron` on `work/*` branches, venv via `ln -sfn ../../.venv .venv` symlink, zero downloads). Agents that hit blockers (tests not working, etc.) must message the parent and WAIT for guidance, never self-resolve by leaving the workspace or editing main. The parent is the sole responsible agent for enforcing adoption/compliance — fix hardstand if broken, do not abandon it. All 8 pre-commit hooks must work correctly INSIDE each workspace and BLOCK commits until green — verify by planting a violating commit (e.g. overlong docstring) inside a workspace and proving pre-commit refuses it, then a clean commit lands.

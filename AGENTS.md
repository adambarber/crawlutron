# AGENTS.md

This file provides guidance to agents working in this repository.

- The service is a stateless execution surface. Callers own frontier queueing, dedupe, persistence, and host-policy decisions; do not add caller state to the service to make a caller's problem easier.
- Agent/bot integrations should use the machine-readable discovery endpoints first (`/.well-known/crawler-service` and `/v1/capabilities`) and follow the durable contract in `docs/references/crawlutron-agent-contract.md`.
- It must not bypass Cloudflare or WAF controls, solve CAPTCHAs, rotate proxies or identities, inject credentials, or continue after an explicit denial. Terminal classifications are reported, not worked around.

## Agent dispatch rules (process)

- **Pre-development review before any feature or fix.** Read the ticket, the modules it touches, and the gates that govern them; state how the change fits the current architecture before writing code. A ticket whose body cites stale paths must be re-grounded from the live tree first.
- **Architectural review gate on tickets.** A GitHub ticket must carry an architectural review (its reach, its design choice, its walk-past plan) before an implementation agent picks it up. A quick `scripts/ticket_arch_review.sh <issue>` check assists the reviewer; it does not replace the review.
- **All development is TDD.** Red first for every behavior; record the red output; then green; then refactor. Budgets and ratchets move DOWN only, in the same commit as the work that earns them.
- **Gates seal shut at zero.** When a gate's offender count reaches zero, delete its budget/exemption table and leave an unconditional assertion — no configuration surface survives a sealed gate. Verify with a mutation check (inject the violation; the gate must name file and line).
- **Document process improvements here.** Any change to dispatch rules, review requirements, or gate doctrine is written into this section in the same commit that lands it.
- **Commit verification trap (2026-10-25, three occurrences):** never pipe a commit through `tail`/`grep` (the pipe swallows pre-commit's exit code — exit 0 with nothing landed); never compound `--no-verify` into a multi-statement command; after every commit attempt verify `git log -1` shows the expected message BEFORE proceeding.
- **Hook budget stays inside turn budgets (rewritten 2026-10-27, gate-speed audit):** every gate runs THROUGH `scripts/gate_fanout`, which starts all gate children at once on the first hook of a run and lets each hook wait only on its own child — wall time is the SLOWEST gate, not the sum. Each fan-out child is hard-killed after `WALL_SECONDS = 60` (`scripts/gate_fanout.py`), so no gate can hang a commit; a hang is a gate defect, never a reason to skip it. Measured on the reference machine (warm): full chain 15.9s — ruff 0.23s, ruff-format 0.17s, basedpyright ~2.8s (pyright until 2026-11-02, 4.28s; basedpyright uses the same config, fails close on a dead include), jscpd 0.17s, mypy 0.17s, vulture 0.18s, safety-invariants 10.0s (`-n 6` xdist; serial 35.6s; slowest legit invariant 3.3s). Every gate still runs on every commit — exclusion, `--no-verify`, and budget raises are forbidden; the jscpd floor tightened 3/30 → 2/30 in the same audit (zero pairs measured over 687 sources). When a gate or invariant test is added, the chain must stay fast enough for a subagent to complete a commit inside one turn; if the warm chain grows past ~25s, parallelize further rather than trimming tests. A cold chain (fresh workspace, no `.mypy_cache`/`.gate_fanout`) is the number a subagent hits on workspace up — keep it under ~60s or pre-warm caches in the workspace setup steps.
- **Subagent dispatch protocol (user directive 2026-10-27, mandatory for every dispatch):** the FIRST thing a dispatched subagent does, before any other work, is validate its environment: (1) confirm `git rev-parse --show-toplevel` and `git branch --show-current` name its assigned hardstand workspace and `work/*` branch — never main, never another writer's workspace; (2) confirm its tools work (`.venv/bin/python` resolves, `pytest` collects, pre-commit hooks are installed); (3) confirm it has the ticket context, directions, and workspace path it needs. If ANY check fails, it MUST send the parent a message describing the failure and HALT until it receives direction — zero improvisation, zero workspace-hopping. Additionally, every subagent ENDS every turn with a SELF IMPROVEMENT REVIEW: what its instructions failed to cover, what process friction it hit, and what the parent should change to make the next dispatch succeed. The child writes it into its final report text (child sessions have no ctx_memory tool); the parent reads every review and folds accepted improvements into this section — the improvement cycle is part of the dispatch itself, not an afterthought. Dispatch-prompt checklist for the parent, from accumulated reviews: name how to read CLOSED issues (`state:"all"`), tell writers to run `ruff check` AND `ruff format --check` before committing (blocked commits are the gate working — never auto-fix to mask them), and state the expected layer/package for ownership moves rather than leaving it to the writer's judgment; writers run the battery with the venv's bin on PATH (`.venv/bin` first — test_repo_tool_resolution needs it, the known-environmental failure otherwise). Workspace commands run through HARDSTAND, not bare shell cd+PATH chains (owner directive 2026-10-28): declared actions — `hardstand run <ws> pytest-fast`, `hardstand run <ws> mypy`, `hardstand run <ws> ruff`, `hardstand run <ws> typecheck` — get the declared env and explicit timeouts; arbitrary one-offs via `hardstand exec <ws> -- <argv>`; NEVER `cd .hardstand/<ws> && PATH=... <tool>` by hand (unmanaged env, no timeout, no declared keys). For type-checker evidence prefer adding a declared action in hardstand.toml over shell chains.. Pre-flight additions (2026-10-27, BU review): every writer merges main FIRST (`git merge main --no-edit`) — ticket-referenced files may have moved since the branch diverged; grep tests/ and docs/ for a source path string before any `git mv` (four path-pinning invariants need same-commit edits); tools with path parameters get ABSOLUTE in-workspace paths (ast_grep_replace resolves against the parent checkout otherwise). Further additions (2026-10-27, BV review): "re-derive the defect from the live tree before coding" is a standard clause on every bug ticket — a ticket's prescribed fix may be architecturally wrong (BV proved it on #560); after a failed issue-tool write, verify via a read before retrying, and if reads also fail, note the attempt and STOP writing (outcome-unknown writes are untracked state); degraded-mode writes use a bounded cadence — at most one retry per major work phase, never a loop — and report tool-reported success as UNVERIFIED until a read confirms. On degraded GitHub, writers pre-authorize commits citing the ticket number from the dispatch (commit-msg gate needs it); the parent reconciles bodies when GitHub recovers. BW additions (2026-10-27): new detector/gate tests must themselves be gate-clean — public app doors only, docstrings ≤3 lines, no clone-pairs between sibling tests — extract the shared sweep before committing; when the private-imports gate blocks a test, the fix is a public door (rename + `__all__`), not an exemption; mutation checks on AST gates are done with in-memory AST probes, never shelling a mutated tree (stale pycache corrupts collection and can't be cleanly undone); mutation checks on RUNTIME code use a scratch-dir tree copy (mutate the copy, pytest the copy, discard) — never mutate the workspace in place. Dispatch prompts state the comment limits up front (≤2-line comment runs, ≤3-line docstrings) and say "check whether X already landed" for work whose dependencies recently merged; multi-hundred-line rewrites go through whole-file write from the git base, not line-range edits (a bad range can truncate the file tail); the same rule binds any edit spanning >20 lines. CA additions (2026-10-28): `ls tests/_*.py tests/invariants/_*.py` before creating a support module (two existing helpers were clobbered by name collision); run the jscpd gate locally before committing extraction/move work (clone-pairs with leftover originals are the predictable failure); moved code must be type-clean in its new home — mypy scope covers tests/**/_*.py even if the source test module was never checked; when repointing test doubles, preserve call signatures, not just import lines; probe GitHub degradation with a READ (show_issues), never a write.
- **Workspaces never diverge (user directive 2026-10-27):** a settled writer's branch merges into local main BEFORE the next writer dispatches into that workspace — no long-running diverging workspaces. The parent audits divergence (`git rev-list --count main..work/<name>` and `HEAD..main`) at every dispatch and every merge; a workspace found ahead of main unmerged is landed immediately (battery-verified) before new work. A writer starting in a shared workspace runs `git merge main --no-edit` as its first act.
- **Hardstand adoption mandate (user directive 2026-10-24):** all implementation agents run inside their hardstand workspace only (config: hardstand.toml, workspaces under `.hardstand/` INSIDE `~/Projects/crawlutron` on `work/*` branches, venv via `ln -sfn ../../.venv .venv` symlink, zero downloads). Agents that hit blockers (tests not working, etc.) must message the parent and WAIT for guidance, never self-resolve by leaving the workspace or editing main. The parent is the sole responsible agent for enforcing adoption/compliance — fix hardstand if broken, do not abandon it. All 8 pre-commit hooks must work correctly INSIDE each workspace and BLOCK commits until green — verify by planting a violating commit (e.g. overlong docstring) inside a workspace and proving pre-commit refuses it, then a clean commit lands.
